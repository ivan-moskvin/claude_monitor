# claude-divoom

Панель с лимитами Claude на экране [Divoom Times Gate](https://divoom.com/products/time-gate).

Третий потребитель `~/.claude/usage-snapshot.json`: читает тот же файл, что и строка
статуса, рисует панель 128×128 и отдаёт её одному экрану устройства. Остальные четыре
экрана не трогает.

```bash
go build .                 # сборка
./claude-divoom -login     # один раз: получить LocalToken устройства
./claude-divoom            # мост: обновляет панель, пока запущен
./claude-divoom -once      # отправить один кадр и выйти
./claude-divoom -preview panel.gif   # посмотреть кадр, не трогая устройство
```

Настройки — `~/.claude/divoom.json` (создаётся `-login`, права 600):

```json
{ "ip": "192.168.1.121", "local_token": 156587, "lcd_index": 4, "port": 8477 }
```

`ip` можно оставить пустым — устройство найдётся через облачный каталог Divoom по
общему публичному адресу. Это единственный запрос наружу; со `ip` в конфиге мост
работает только по локальной сети.

## Протокол Times Gate

Проверено на прошивке Hardware 400. Знание неочевидное и добыто эмпирически —
без него команды «выполняются» и ничего не происходит.

- **`LocalToken` обязателен** для всех команд рисования. Без него прошивка отвечает
  `error_code: 0` и молча игнорирует команду. Токен виден в настройках устройства
  в приложении Divoom, либо берётся из `Device/GetListV2` после входа в аккаунт —
  это и делает `-login`.
- **`error_code: 0` не значит «нарисовано»** — только «команда разобрана».
- **`"Request data illegal json"` — это «неизвестная команда»**, а не ошибка разбора
  JSON: несуществующая `Totally/Bogus` даёт тот же ответ. Так, `Draw/SendHttpItemList`
  на этой прошивке отсутствует, хотя описан в документации TimeGate.
- **`Draw/SendHttpGif` не рисует.** Принимает кадр (base64 JPEG, `LcdArray`, размеры
  16/32/64/128), отвечает нулём — и не показывает ничего.
- **Рабочий канал — `Device/PlayGif`**: устройство само скачивает GIF по ссылке.
  Поэтому мост поднимает локальный HTTP-сервер и присылает ему адрес. Порт
  фиксированный: после перезапуска моста на экране висит ссылка со старого запуска,
  и она должна продолжать работать.
- Хэш кадра в имени файла — то, что заставляет устройство перекачать картинку:
  по прежнему адресу оно показывает прежнее изображение.
- Экраны адресуются `LcdArray: [0,0,0,0,1]` (пятый), а не `LcdIndex`.
- Устройство приходит за картинкой отдельным запросом, с задержкой: разовая
  отправка обязана дождаться этого запроса, иначе сервер закроется раньше.

Полезные команды при отладке (`POST http://<ip>/post`):

| Команда | Зачем |
|---|---|
| `Channel/GetAllConf` | яркость и `LightSwitch` — включён ли экран |
| `Channel/OnOffScreen` + `OnOff` | включить экран; без параметра гасит все пять |
| `Channel/SetClockSelectId` | вернуть экрану обычный циферблат |
| `https://app.divoom-gz.com/Channel/Get5LcdInfoV2?DeviceType=LCD&DeviceId=<id>` | текущая раскладка всех пяти экранов, чтобы её восстановить |

## Панель

Три полосы, как в строке статуса: пятичасовое окно, время до сброса, недельное окно.
Пороги цвета — те же (до 60% базовый, до 85% оранжевый, дальше красный), живут в
`usageWindow.tint`.

Отдельно показываются два состояния, без которых панель врёт молча: снапшот старше
90 секунд («СТАРЫЕ» — данные растут только в активной сессии Claude Code) и сброшенное
окно («СБРОС» — проценты описывают прошедшее окно, расход обнуляется).

Шрифт — свой битмапный 5×7 в `font.go`; шрифтовых движков в зависимостях нет.
Буквы «Ч» в нём нет намеренно: в такой сетке она неотличима от четвёрки, поэтому
время пишется как `2:38`.
